# 文本匹配任务实验报告

本报告完成仓库中的四种文本匹配方法：PointWise、DSSM、Sentence BERT 和无监督 ESimCSE。所有实验使用相同的本地中文编码器 `BAAI/bge-small-zh-v1.5`，由 `run_matching.py` 统一训练、选取验证集最佳模型、评估独立测试集并演示预测。前三种方法在同一商品评论数据划分上比较；ESimCSE 使用 LCQMC 数据，分数不能与前三者直接比较。

## 数据检查与划分

原商品评论训练集有 1,416 对，验证集有 352 对；原划分中 277 条评论同时出现在训练集和验证集。合并后去重得到 1,708 对，按评论文本分组、随机种子 42，重新划为训练 1,199 对、验证 255 对、测试 254 对。三个划分中的评论文本互不重叠。正类 `1` 表示商品类别描述与评论匹配，负类 `0` 表示不匹配。

LCQMC 的 `train.txt` 有 477,532 行，去重并排除验证、测试句子后保留 217,790 条未标注文本。仓库提供的 `test.tsv` 有 12,500 对但没有标签，因此只用于排除训练文本，不用于计算指标。将带标签的 `dev.tsv` 按共享句子的连通分组划为验证 4,403 对、测试 4,399 对；两者之间也没有相同句子。具体数量、标签分布和原文件 SHA-256 见 [数据审计](runs/full/data_audit.json)。固定划分文件保存在 `runs/full/data/`。

## 实验配置

本地环境：Windows、Python 3.11.16、PyTorch 2.13.0+cu130、Transformers 5.16.1、RTX 5080。四种方法均从同一个本地 BGE-small-zh-v1.5 权重初始化，使用 BF16 自动混合精度和随机种子 42。前三种有监督方法各训练 10 轮，批量大小 16、最大长度 128、学习率 5e-5。ESimCSE 在完整清理后的训练文本上训练 1 轮，批量大小 64、最大长度 64、学习率 1e-5，采用原实现的词重复增强。ESimCSE 按固定训练步数评估，其他方法每轮评估；只用验证集选择权重及余弦相似度阈值。独立测试集仅在选择结束后评估一次。

本仓库原示例使用 ERNIE 3.0 base；此次使用的是本机已有的 BGE-small 模型，因而结果不应与原 README 的 ERNIE 数字比较。BGE 本身已经是经过预训练的语义向量模型，其预训练数据是否包含 LCQMC 无法由当前仓库确认；ESimCSE 的指标只应视为本地实验结果。

## 独立测试结果

| 方法 | 测试样本 | 准确率 | 精确率 | 召回率 | F1 | Spearman | 最佳步数 |
|---|---:|---:|---:|---:|---:|---:|---:|
| PointWise | 254 | 0.862 | 0.765 | 0.876 | 0.817 | 0.716 | 675 |
| DSSM | 254 | 0.909 | 0.867 | 0.876 | 0.872 | 0.755 | 300 |
| Sentence BERT | 254 | **0.933** | **0.929** | 0.876 | **0.902** | 0.748 | 675 |
| ESimCSE | 4,399 | 0.757 | 0.717 | 0.852 | 0.778 | 0.602 | 1,000 |

商品评论测试集的多数类准确率为 0.650；LCQMC 测试集的多数类准确率为 0.502。商品评论测试集较小，分数可能随划分和随机种子波动。ESimCSE 的预训练基线在验证集的 F1 为 0.807，微调后最佳验证 F1 为 0.787，说明本次 ESimCSE 微调降低了基线表现；训练损失下降并不等同于匹配质量提升。

三个有监督模型都支持用十个商品类别描述对新评论排序，也验证了 DSSM 和 Sentence BERT 的预计算类别向量与直接成对计算得到相同分数。示例中的苹果评论和衣服评论均排在正确类别首位；手机通话评论被三个模型排在“平板”首位，说明相近电子产品类别仍容易混淆。ESimCSE 示例把语义相近的图片制作问题判为匹配，把天气和软件安装问题判为不匹配。全部原始分数见各方法的 `demo.json` 和 `test_predictions.json`。

## 文件与复现

运行入口：[run_matching.py](run_matching.py)。测试：[test_matching.py](test_matching.py)。完整结果：[summary.json](runs/full/summary.json)。每个方法的目录下有最佳权重 `best/matching.safetensors`、分词器、配置、训练历史、测试指标、逐条预测和推理示例。`runs/` 被 Git 忽略，模型与数据划分仅保存在本机。

在仓库根目录、安装了 PyTorch、Transformers、NumPy、SciPy、scikit-learn、safetensors 的 Python 环境中运行：

```powershell
$env:PYTHONUTF8 = '1'
$env:TOKENIZERS_PARALLELISM = 'false'
python text_matching/run_matching.py train --method all `
  --model E:\Workspace\Beginner\llm-beginner\task-4-rag\models\bge-small-zh-v1.5 `
  --local-only --output text_matching/runs/full --amp
```

运行脚本会拒绝覆盖已有的完整结果；复现实验时指定新的 `--output` 目录。预测示例：

```powershell
python text_matching/run_matching.py predict `
  --checkpoint text_matching/runs/full/sentence_bert/best `
  --text1 '水果：指多汁且主要味觉为甜味和酸味，可食用的植物果实。' `
  --text2 '苹果很甜，新鲜又好吃。'
```

预测输出中的 `score` 是匹配分数，`threshold` 是验证集确定的阈值，`match` 表示是否超过该阈值。DSSM、ESimCSE 的分数是余弦相似度；PointWise、Sentence BERT 的分数是正类概率。
